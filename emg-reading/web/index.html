Calibration

For troubleshooting. Normally the haptics take their levels from the session the running model was calibrated on (every rest cue in every posture and every grip), and start by themselves with the model. This measures each channel's rest and squeeze level from a short recording instead and saves calibration.json, which Start haptics on the Haptics tab uses. The rest level is set high (99th percentile of the rest times 1.5) so the outputs stay off at rest.

Train

    
Every model trains here: LDA (seconds, on the CPU) or the ring network (on the GPU, only on the
      training desktop, needs torch). Both use 200 ms windows of the filtered EMG. Grip sessions (protocols A to D)
      and sign sessions (E and F) train separate models, so they can't be ticked together.

Calibrate a network

    
Fits the per-person transform and the output layer on the chosen repetitions of a session recorded
      at the current band position, scores it on the other repetitions and saves the calibrated network. A sign
      network takes a sign session; there the repetitions are its rounds (round 1 is the first time each sign comes up
      in each posture). LDA models don't need this, train one on the new session instead.

    

      
      
      
    

    

    
Evaluate networks

    
Grip sessions only. Leaves each session out in turn, trains on the others and tests on it, without
      and with a 2-repetition calibration, against LDA on the same windows. Newest only scores the newest session on a
      network that hasn't seen it, do that before training on a new session. Uses the epochs above.

Finger angles

    
Grip networks only. White: the hand the camera tracks. Orange: the angle head, trained to ignore how
      hard the muscles fire. Magenta: the effort head, trained to use it (a finger bent halfway against fully). Both come
      from the same pass of the network. Drag either to turn both. The match compares each with the camera on the base
      and middle joints; the joints the network doesn't predict yet (spread, finger tips) are drawn relaxed.

    

      

      

    

  






  

    
Grip control

    
The model's output drives a virtual hand. Effort is each channel's envelope scaled between the rest
      and max levels of the model's newest training session, or the session a network was calibrated on (the haptics'
      levels), mean over the channels with pad contact. In rules mode the mapping says which pattern picks which pose;
      while a pose is held, squeezing closes the hand in proportion to effort. Every setting applies straight away
      while it runs.

Mapping

    
Each line: if a trigger happens in a pattern, then do this. Clench is effort above the clench level,
      in any hand shape; the other triggers are the model's classes, on while their probability is at least the
      threshold. Held: on for at least this long. Repeated: this many short times with pauses under the pause time
      in between; held 0 s acts on the first step the trigger is on. The first list runs while relaxed (no grip),
      the second while holding a grip. A pose picks it (while holding it switches at the same closure), release goes
      back to relaxed, close and open move the hand while their trigger stays on. The higher rule wins when two fire
      together. Hover a pose in the Then list to see it. Changes apply straight away.

Cursor

    
A fixed map from muscle activity to a dot, nothing is trained: you learn the map. Each channel's
      level (envelope between the rest and max levels of the chosen session, the haptics' levels) pulls the dot
      towards that electrode's direction, so which side of the forearm works sets the direction and how hard sets the
      distance. Relaxed sits in the middle. With targets on: hold the dot in the middle, a target lights up, get in and
      stay for the dwell time. Every target run is logged to data/cursor/.

Sync

    
Sessions can be recorded on any computer, the networks train on the desktop with the GPU (the
      hub). This computer sends its finished sessions to the hub, the Train tab can train there, and the models it
      saves are downloaded here to run with this computer's armband.

    

    

      
Hub

      
The hub's address on the tailnet and the token it made for this computer
        (python hub.py add-device NAME on the hub, which runs the app with --hub).

      

        
        
      

      

      

      

      
Sessions

      
Sends every finished session the hub doesn't have yet, stopped early ones too (training leaves
        those out by itself). A broken connection carries on where it stopped on the next send, and a session only
        appears on the hub once every file arrived intact. Nothing on either side is overwritten.

      

        
        
      

      

      
Models

      
The hub's models that can run live. A model comes with the session its effort and haptic
        levels are taken from, if this computer doesn't have it. Downloading also swaps Control mappings and
        profiles both ways; where both computers have one of the same name, each keeps its own.

      

      

      

      

      

      

    

  






  

    
Dev

    
For trying out page changes without recording. Nothing here is saved. Tests of changes that are

Short run

      
A real practice run with the protocol and postures picked on the Record tab, cut to a few cues
        of at most 1.5 s and without breaks, so the cue panel, Mark bad, Stop and the end card can be tried in
        seconds.

Armband WiFi

    
After the armband is switched on: forgets and rejoins its WiFi, switches
      the adapter to DHCP for 5 s so the band sees an address request, then back to the static 192.168.4.2, and
      restarts the stream. Asks for admin rights on the PC's screen. About 15 s.

    
After the armband is switched on: finds its network, joins it, waits for
      an address from the band and restarts the stream. The Mac has one WiFi adapter, so it leaves the home network
      and the hub; rejoin the home network from the WiFi menu to sync. About 10 s.

    

      
    

    
    

    

    
Armband battery

    

    
The drain rate comes from the last 15 minutes and needs about 5 minutes of streaming and a drop of
      at least 1 % before it shows. Don't run the armband flat, it was recovered from a deep discharge once already.
